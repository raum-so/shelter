# Shelter 0.8.2

This release lets customers use their root domain, such as `customer.com`, for
an app hosted on Shelter. Use an ALIAS, ANAME, or flattened CNAME at the
customer's DNS provider. Subdomains such as `www.customer.com` continue to use
a regular DNS-only CNAME.

## Connect a root domain

Open **Project → Domains → Add domain → External customer domain** and enter
the root hostname. Shelter shows the routing record and the TXT ownership
proof. Once DNS matches the configured destination, Shelter registers the
hostname with Cloudflare for SaaS and displays any additional TXT challenge.
The route becomes available when Cloudflare activates the exact hostname and
its HTTPS certificate and the project has a ready deployment.

The project domain API now reports `external.dnsMode` and can return an
`ALIAS` instruction. Existing subdomain bindings retain their CNAME mode
when the database is upgraded. The same Cloudflare for SaaS fallback and
tunnel serve both types of domain.

## Upgrade and validation

Install the immutable release using the [release installer](../RELEASES.md).
Before rolling back to a subdomain-only version, remove apex bindings on
0.8.2 so Shelter can clean up their Cloudflare resources. See the
[external domain guide](../EXTERNAL-DOMAINS.md) for setup and recovery.

A live test used Cloudflare DNS flattening at a disposable root domain and a
regular CNAME at a second hostname. Both reached the test app through the
existing tunnel with HTTP 200 and valid HTTPS. The app received the original
Host in both cases. ALIAS and ANAME use the same public address checks.
