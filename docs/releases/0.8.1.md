# Shelter 0.8.1

This release helps external customer domains obtain HTTPS certificates when a
Cloudflare Single Redirect would otherwise redirect the certificate-validation
request before the certificate exists.

## Certificate validation setup

- Cloudflare for SaaS basic setup can inspect enabled Single Redirects and
  preview an exception for `/.well-known/acme-challenge/` before applying it.
- Only the selected zone's redirect expressions change. Redirect destinations,
  status codes, query handling, rule order and disabled rules are preserved.
- Existing exceptions are recognized on subsequent setup attempts. Changed
  rules, expired previews, unsupported rules and missing permissions produce
  actionable errors instead of silently saving incomplete setup.
- Original rules are encrypted in the local database before a write. After a
  partial failure, a new preview shows the remaining changes; Shelter does not
  overwrite newer operator edits with an automatic rollback.
- The administrator-only preview API supports the same workflow. Existing
  setup calls without a preview token retain their read-only provider behavior.

## Upgrading

Back up the data volume and retain `APP_SECRET`, then install the verified
immutable release using the [release installer](../RELEASES.md). Existing
customer domains, projects, tunnels and saved CNAME destinations are preserved.
Installing the update does not change Cloudflare rules automatically.

Open **Settings → Cloudflare → Cloudflare for SaaS — basic setup** and keep
**Allow certificate validation automatically** selected. Review the proposed
changes and choose **Apply exception and save**.

For OAuth, allow **Dynamic URL Redirects Write** (`dynamic-redirect.write`) in
your registered Cloudflare client and use **Reconnect for automatic exceptions**
in the setup if prompted. Adopt the replacement connection using the existing
account and tunnel. Do not disconnect first. This additional permission is
optional for normal Shelter operation and is requested only for this feature
or to retain an existing grant. API-token users can add the equivalent
zone-scoped **Dynamic URL Redirects Edit** permission.

If you prefer to manage rules manually, clear the checkbox and follow the
[manual exception and recovery guide](../EXTERNAL-DOMAINS.md#allow-certificate-validation-through-redirect-rules).
Cloudflare for SaaS must still be enabled with an active fallback; this update
does not configure its billing, DNS or fallback origin.

## Validation and limits

Automated tests cover preview approval, unchanged redirect actions and order,
idempotent retries, expired and session-bound previews, drift, partial failure,
permission upgrades, CSRF and project-token restrictions. The complete local
check includes the existing installer, release, server, web and CLI checks.

The automatic flow has not been exercised against live Cloudflare writes.
The earlier customer-domain pilot passed certificate issuance after the same
path exception was applied manually. Bulk Redirects, Workers, Page Rules,
WAF and application redirects are outside this automated check. Do not edit
the same rules concurrently: the provider API offers no documented atomic
version precondition. Verify a disposable customer domain end to end before
relying on this flow for a new installation.
